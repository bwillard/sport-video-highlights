# Soccer Clips

Tag clips from full-game Veo videos, follow and name the players, watch one player's game, and build highlight reels. See [plan.md](plan.md) for status and design, and [plans/](plans/) for each phase.

# Setup
 - `conda env create -f environment.yml` (creates `soccer_clips_env`; includes ffmpeg >= 6 from conda-forge)
 - `conda activate soccer_clips_env`
 - `pip install -e .`
 - `cp .env.example .env` and fill in the data directories. `.env` is gitignored; never commit real paths. RunPod keys go there too if you use cloud GPUs (see `.env.example`).

# Dev Instructions
 - `conda activate soccer_clips_env` (the ffmpeg in miniconda's base env is too old; config checks for >= 6)
 - Run tests: `pytest`

# Usage

## Games and the server
 - Drop new Veo downloads into `$SOCCER_FULL_DIR/<year>/`. The filename (minus `.mp4`) becomes the game id; it should end in `YYYY-MM-DD`.
 - `soccer-clips scan` registers new videos (also runs when the server starts).
 - `soccer-clips list` lists registered games.
 - `soccer-clips serve` runs the web server on `SOCCER_HOST:SOCCER_PORT` from `.env`. It restarts itself when the code changes (so fixes made in the tagger always use the current ball filter), waiting until no export or reel render is running, since those live in the server's memory; `--no-reload` turns that off. The pages are read from disk, so a browser reload picks up page changes.
 - Every page has the same row of links at the top: **Tagger** (`/`), **Player view** (`/watch`), **Roster** (`/roster`), **Reels** (`/reel`), **Ball labels** (`/label-ball`) and **Other balls** (`/review-balls`).

## Tagging clips and reels
 - Open `http://<server>:<port>/` to tag clips; the keyboard shortcuts are listed under the video, in fold-out sections (playback, clips, game time, callouts, ball, players). Tags and their 1–9 hotkeys are in `$SOCCER_GAMES_DIR/tags.json` (created with defaults on first run; edit by hand). `F` tags the player number in `SOCCER_DEFAULT_PLAYER` (`.env`), `P` adds any other number, `T` marks a team play; the "who" filter picks a player or team plays for exporting or reels. `Z` turns on a magnifier that follows the mouse (`Shift+Z` 3× / 6×).
 - Exported clips go to `$SOCCER_CLIPS_DIR/<year>/<game_id>/<clip_id>.mp4`.
 - Reels: in the tagger, filter the clip list and press "Add shown to reel". Open `/reel` to render (preview or full), watch, jump back to the full game with `G`, and download. Each render can include your notes and callouts, callouts only, or neither (the "with" menu), so you can keep an annotated version and share a clean one. Renders go to `$SOCCER_REELS_DIR/<reel_id>/<preset>[-<variant>].mp4`. Full renders use the GPU's video encoder when there is one (about 5× faster here); speed and quality settings are in `.env` (see `.env.example`).
 - Title cards: each reel gets an opening card (its title) and a card before each clip (time in the game + the clip's note). Each card stays up long enough to read its text (0.75s + 17 characters/second); the "cards ≥" box on the reel page sets the minimum (default 2s; 0 turns cards off).
 - Callouts: in the tagger, select a clip, pause on a moment inside it, press `C` and click on her (drag to size the ring). Reels freeze there with her spotlighted (1.5s with caption overlays, 0.75s with title cards); set the length in the "freeze" box on the reel page (0 turns it off).
 - Game info: set each game's date and a short description (e.g. "Home vs SAA, 3-1 win") in the box at the top of the tagger's right-hand panel. Reel opening cards show them under the reel title.
 - Descriptions: each clip's game time and note are shown as a caption over the start of the clip (default) or as a title card before it; pick per reel with the "descriptions" menu on the reel page.
 - Game time: the tagger's Game time box holds when each half starts and ends (H / Shift+H for the kickoffs, J / Shift+J for the ends; the links jump to each, and non-game time is shaded on the timeline). "suggest times" proposes them from the player tracks (`soccer-clips gametime suggest <game|all> [--apply]`). "cut video to game time…" (`soccer-clips gametime cut <game> --yes`) makes a copy of the video with only the two halves (plus 10 s either side), without re-encoding, in `cut/` next to `full/` (or `SOCCER_CUT_DIR`; the original is kept), and moves everything for that game onto it: clips, labels, ball and player tracks, bench clips, reels' jump-back. Anything in non-game time is dropped. A backup goes to `backup/` first; "undo cut" (`soccer-clips gametime restore <game>`) puts it back. After a cut, GPU jobs upload the cut video (the network volume still holds the originals). All seven games so far are cut.

## Following and naming players
 - Player tracking: person boxes are detected once per model on a rented GPU, `soccer-clips gpu run people-games --mode callouts|clips|all --models yolo11m [yolo26l ...] [--games ...]` (from the game videos on the network volume; locally `soccer-clips people detect <game|all> --mode ... --model ...`, very slow on a CPU), into `tracks/people_raw_<model>.npz`; stretches already detected are skipped. `soccer-clips people track <game|all> [--model yolo11m] [--tracker botsort|bytetrack] [--buffer 30]` turns saved boxes into tracklets here (`tracks/people_<model>.npz`, seconds per game), using the camera motion from `ball_raw.npz`. `soccer-clips people eval yolo11m [yolo26l ...] [--saved]` scores them at the callouts (`--saved`: the saved tracklets as they are, in seconds, instead of tracking again): is there a box under each one, and how much of its clip that box's track covers. Every game has whole-game tracks.
 - Kit colour and teams: `soccer-clips people kit <game|all>` works out the shirt and shorts colours of every detected player (~7–9 min a game, all CPU cores), and `soccer-clips people track` then uses it: a track can't jump to someone in a different kit, tracks are cut where the kit changes, and short gaps are bridged in the same kit (settings `--kit-gate`, `--split-kit`, `--link-gap`, `--link-kit`; `0` turns one off). Players are grouped into teams by kit per game. 'Ours' is the kit your labelled players wear (worked out from all the boxes your labels cover, so a kit that looks different in sun and shade is still one team; any labelled stretch counts as ours; each box's team is smoothed over a few seconds of its track); `soccer-clips people teams <game|all>` redoes the grouping in seconds. `soccer-clips people eval-labels [--saved]` scores tracking against your player labels: how long the tracklet under each label lasts, how often a tracklet strays onto someone else, and how many of your 'wrong person' fixes are still wrong.
 - Following a player in the tagger: press `V` (or 👥 players) to see tracked people as thin boxes (white = our team, blue = opponents, grey dashed = refs, keepers, spectators; which teams get boxes is in the 🔍 layers menu, our team only to start, `Shift+D` opponents + others) and an orange ring under the player chosen next to it. Pause, press `L` and click the player: the whole tracklet under the click (a stretch the tracker kept on one person) is labelled as them. When the ring jumps to someone else, `Shift+L` removes it from there on; `U` takes back the last label. The orange strip under the timeline shows where they're labelled. A small white #number sits over everyone already labelled. Labels are saved as clicks in the game's `tracks/people_picks.json`, so they still apply after re-tracking.
 - Only them: `W` (or ⏭ only them, next to the follow picker) plays just the stretches where the followed player is on screen, labelled or guessed, and skips the rest (darkened on the timeline); `W` again plays everything.
 - Recognition by appearance: a fine-tuned OSNet-AIN model turns crops of each tracklet into signatures, and every labelled player gets a 'look' from their labels in every game. Where an unlabelled teammate looks enough like one player (the "auto-label at" slider in 🔍 layers, 0.80–0.98, default 0.90, remembered) and clearly more than anyone else, the tagger shows a dashed ring and a faint `#38?`. Paused, point at a player (cyan box): `Y` / `X` answer a guess (or label anyone with who they look most like); click a player to pick any number from a box listing the closest looks. `A` walks every automatic guess in the game (`Shift+A` back), `G` walks the unlabelled teammates that look most like the followed player; `Y` yes, `X` no and on to the next. "names with numbers" in 🔍 layers shows first names from the roster beside the numbers.
   - Data: `soccer-clips reid crops [--games ...]` cuts player crops from each tracked game (`tracks/reid_crops.npz`); `soccer-clips reid sigs [--games ...] [--device cpu|cuda]` computes signatures (`tracks/reid_sigs.npz`, about 17 crops/s on this CPU; GPU job `reid-sigs`), with the fine-tuned model `models/reid_osnet_ain.pt` if there is one, else stock `osnet_ain_x1_0_msmt17.pt`. Fine-tuning runs on RunPod (`soccer-clips gpu run reid-train`, or the roster page's Retrain button). `soccer-clips reid auto-eval` scores the automatic labels by hiding half of each player's labels; `reid experiment` is the cross-validated training/scoring run used on the pod.
 - Roster (`/roster`): names for numbers (kept in `$SOCCER_GAMES_DIR/roster.json`, never in the repo), and every stretch of a tracked player from every game as a picture (start, middle and end crops), filterable by game. Views: a player's labelled pictures (least like them first, so wrong ones gather at the top), "probably #N" (unlabelled, looking 0.9 or more like them and clearly ahead of anyone else), unassigned (our team, unlabelled) and doubtful labels (someone else almost as likely). Select pictures (click, Shift+click, Ctrl+A, arrows) then type a number and Enter, or drag them onto a name; Backspace unlabels, `N` = not our team, `S` (✂) splits a picture of more than one girl where each new girl starts, `U` undoes. The "▶ player view" link by a player's name opens the Player view on them.
 - Player view (`/watch`): one player's games played straight from the game videos with everything else skipped; nothing is rendered. Pick a player and one game or every game. Stretches are where they're labelled, plus ("likely too") where the recognition is sure, with a second of lead-in and lead-out and gaps under 3 s played through; the next stretch is loaded in a second, hidden player, so the cuts are seamless. The ⚽ slider plays only the moments the game ball comes within so many of their heights of them (at them, 0.5, 1, 1.5, 2, 3, 5), with **before** / **after** seconds of build-up and follow-through (3 s and 2 s to start). **Highlight them** (`H`) marks the player on the video: ring, box, arrow, spotlight and/or name, with colour, size, dimming and smoothing, dashed where placed by appearance rather than labelled. Keys: Space, ← / → 5 s, `[` / `]` stretches, `M` sound, `F` full screen, `T` opens the tagger at that moment. Settings are remembered per browser and the player, game and filter are in the link.

## The ball
 - Ball labels: open `/label-ball` to mark where the ball is, frame by frame. Click the ball (Shift+click if it's hidden behind someone, drag to size it), `N` for no ball, `S` if you can't tell; a magnifier follows the cursor, and holding `Q`/`E` shows 3 frames earlier/later. Frames come in sets kept apart so models are never scored on frames they trained on: `soccer-clips ball sample bench` (150 frames over the benchmark clips, for scoring) and `soccer-clips ball sample train -n 200` (random frames from the games, for training). For training sets, `soccer-clips ball guess train` pre-computes the model's best guess per frame (YOLO11m on the centre crop, ~1 frame/s on the CPU); the page shows it as a dashed blue ring and `Enter` accepts it. Bench frames never show guesses, so they stay an independent test. `soccer-clips ball` shows progress; `soccer-clips ball score [--results results-l4]` scores each benchmark variant's ball detections against the bench labels. Fine-tuning: `soccer-clips ball export` turns the train labels into a YOLO dataset (`labels/dataset/`, 1280×720 native-resolution crops), `soccer-clips ball train yolo26x [more bases]` fine-tunes on it (GPU; 60 epochs, a checkpoint every 5, keeping the one that scores best on the validation frames; weights go to `models/ball_<base>.pt`), and `soccer-clips ball eval yolo11m ball_yolo11m [--frames-file ...]` scores any models on the bench frames (or a listed subset). Labels live in `labels/` next to the games folder (`ball.jsonl`, latest answer wins).
 - Other balls: spare balls by the sideline or balls on the next field aren't the game ball, but they are balls, so the detector should find them (picking the game ball is the tracking filter's job). `soccer-clips ball others find` runs the fine-tuned model over every labelled frame (~14 s/frame on the CPU, saving as it goes) and lists what it finds besides the game ball; review them at `/review-balls` (`Y` ball, `N` not a ball, `S` can't tell). On the labelling page, `O` switches to adding other balls by hand. Training boxes every confirmed ball, and scoring reports found (game ball), real (detections on any real ball) and junk per frame. `soccer-clips ball others` shows counts.
 - Game-ball tracking: `soccer-clips ball track <variants> [--results results-l4] [--draw]` turns a benchmark variant's per-frame ball detections into one game-ball path per bench clip (camera motion cancelled, detections linked, best chain chosen, gaps up to 1 s filled) and scores it against the bench labels next to the "most confident detection" baseline. `--draw` writes review videos (`<clip>.track.mp4`: green ring = detected, yellow = filled, grey = every detection, white cross = your label).
 - Ball in the tagger: press `B` (or the ⚽ button) to ring the game ball wherever it has been tracked (solid: seen; dashed: filled gap; the header says when a stretch isn't tracked). Tracks live in each game's `tracks/` folder (`ball_raw.npz`: detections + camera motion, `ball.npz`: the path). Make them with `soccer-clips gpu run ball-games [--mode clips|all] [--games ...]` (tagged clips cut into segments and uploaded, or whole game videos), or locally with `soccer-clips ball track-game <game|all> [--mode clips|all]` (very slow on a CPU); `--retrack` redoes the path from saved detections after changing the filter. `soccer-clips ball fixed-objects <game|all>` finds things that never move all game (a flag, a chair, a bag up the hill: detected nearly every moment their spot is in view, for a minute or more) and blocks those detections from ever being the ball, then redoes the path; ~15 min a game on the CPU the first time (registering frames to keyframes, then linking keyframes that show the same place), seconds after that, kept in `tracks/world.npz` and `tracks/fixed.npz`. Re-run it after re-detecting a game. `soccer-clips ball eval-games` scores those whole-game paths (rebuilt without hand fixes) at every labelled frame in the games, per game: the check for filter changes that the short bench clips can't show (camera drift over minutes).
 - Debug layer: `D` (or "ball detections (raw)" in the tagger's 🔍 layers menu) draws every ball detection with its confidence (dim below 0.25), your fixes (magenta dot = placed ball, red × = suppressed detection), other balls you marked (cyan), detections on fixed objects (orange, "fixed"; never the ball) and the dashed centre crop the detector searches. A detection with no ring was dropped by the filter; no circle at all means the detector never found the ball (or it was outside the box).
 - Fixing the ball while watching (ring on): `K` then click the ball = it's here; `Shift+K` = that ring is wrong and there's no ball to see. The path is redone around the fix in a couple of seconds, fixes are kept in `tracks/ball_fixes.json` (they survive re-running the filter), and unless switched off ("fixes → don't label" next to the ⚽ button) each fix also becomes a labelled ball frame: most go to the training set, one 30-second moment in five to the benchmark, and anything near a benchmark clip to the benchmark.
 - Other balls while watching: `K` then `O` (`O` on its own still marks a clip's out point), then click each spare or next-field ball (cyan ring); click one again to remove it, `O`/`Esc` to stop. They're saved with the frame's label (as on the labelling page), so training boxes them as balls instead of learning them as background, and scoring doesn't count detections on them as mistakes. An unlabelled frame is labelled first, taking the ring as the game ball (fix it with `K` first if it's wrong). Clicking on a detection (debug layer) takes its exact centre and size; this also works for `K`.

## Retraining from the app
 - The roster page's **Recognition model** panel and the ball labels page's **Ball model** panel show the model in use (when it was trained, what it learned from, its scores against the model before training and a random guess, the last three runs side by side, how many labels have come in since) and an estimated time and cost, with a button to run it on RunPod. Pressing the button is your go-ahead for that run.
   - Recognition (`soccer-clips gpu retrain-reid`): fine-tunes on every labelled player, scores each player's top-1 on games the model never saw (averaged so every player counts equally), keeps the new model only if it beats the stock one and isn't more than 5 points worse than the one in use, then re-signs every game.
   - Ball (`soccer-clips gpu retrain-ball`): fine-tunes on the training labels, scores old and new on today's bench and on the frames you've fixed since, and keeps the new model unless its balance of balls found and finds real on the bench drops by more than a point. **Re-track every game** (`soccer-clips gpu retrack-balls`) is a separate button: every game's ball path again with the model in use, your hand fixes put back.
 - Jobs run detached from the server (a restart doesn't stop them); status is in `gpu/retrain.json` / `gpu/ball-retrain.json` next to the games folder, the log in the run's folder. Each pod deletes itself at its time limit even if this machine dies, and the server deletes any overdue pod every 10 minutes (`soccer-clips gpu sweep` by hand).

## Benchmark clips
 - Tracking benchmark clips: a small fixed set of test clips in `bench/` next to the games folder (or `SOCCER_BENCH_DIR`). The list is `bench/clips.json`: edit a clip's `start_s`/`end_s` (game time), or delete an entry, then run `soccer-clips bench cut` to recut only what changed (`--force` recuts all). `soccer-clips bench add <game_id> <clip_id> <name> [--why "..."]` adds a tagged clip, with its callout if it has one; `soccer-clips bench` lists the set. `soccer-clips bench run [variants]` runs the detection/tracking benchmark into `bench/results/<variant>/` (needs the tracking packages from `environment.yml`), and `soccer-clips bench draw <variant> [clips] [--results results-l4]` draws its boxes onto the clips for watching (`--results` picks another results folder, e.g. one copied back from a GPU machine).

## Cloud GPUs (RunPod)
 - Put `RUNPOD_API_KEY=...` in `.env`. `soccer-clips gpu run <job>` (`ball-train`, `ball-games`, `people-games`, `reid-train`, `reid-sigs`) starts a Secure Cloud pod in a US data centre (`--countries` to change; RTX 4090, else 5090 / L40S), uploads only the files the job needs (listed in the run folder's `uploads.txt`) plus the committed code (`git archive`, so never `.env`), runs the job, copies the results back, then wipes and deletes the pod whatever happens. The pod also deletes itself after `--max-hours` (default 4) in case this machine loses contact; for that the API key is sent to the pod over ssh into a root-only file, and goes with the pod. Each run's log and results are in `gpu/<run id>/` next to the games folder. `soccer-clips gpu` lists our pods; `soccer-clips gpu cleanup` deletes them.
 - Network volume (persistent storage on RunPod, so game videos and the ball model aren't uploaded every run): `soccer-clips gpu volume create [--dc US-KS-2] [--size 50]`, `soccer-clips gpu volume fill` (uploads the videos and model over RunPod's S3-compatible API, no pod needed; put `RUNPOD_S3_ACCESS_KEY` / `RUNPOD_S3_SECRET_KEY` in `.env`), `soccer-clips gpu volume` (status), `soccer-clips gpu volume delete --yes` (removes it and the footage on it). With a volume, GPU runs first upload anything new over S3 (before a pod exists, so no GPU waits), then start in its data centre (any of 4090 / 5090 / L40S / RTX 6000 Ada / L40 / A6000, A100 as a last resort), send only files the volume doesn't have yet, and if nothing is free there for 20 minutes run elsewhere in the US and upload instead (`--no-fallback` to wait, `--no-volume` to skip it). The volume bills monthly (~$0.07/GB) until deleted; the footage stays on RunPod's storage meanwhile.
